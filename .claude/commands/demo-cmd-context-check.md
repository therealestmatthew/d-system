# Context check

$ARGUMENTS

Report what is currently known about the work above — or about this conversation, if nothing was
named — and what is missing. Makes the invisible visible.

## Two lists, and the second one is the point

**Known.** What you actually have: what was said in this conversation, what was supplied as
material, what any project instructions state. For each item, say **where it came from**. A fact
whose source cannot be named is not a known fact, and belongs in the second list.

**Missing.** What you do not have and would use. This is the useful half, and it should be the
longer one.

Do not pad the known list to look well-informed. An honest short list is the whole value of the
command.

## Rank the gaps by what they would change

An unranked list of gaps is as unhelpful as no list, because the person cannot tell which one to
close first. For each missing item, state:

- **What it would change** if it were known — which decision, which output, which recommendation.
- **How much.** Some gaps would redirect the work; others would refine it. Say which.

Order the list by that, most consequential first. Then state plainly **which one to close first**
and why.

## Distinguish three kinds of not-knowing

Collapsing these sends the person to the wrong remedy:

- **Never supplied** — nobody has said it. They can just tell you.
- **Supplied but ambiguous** — it was said in a way that admits two readings. Name both readings.
- **Assumed** — you have been proceeding as though something is true without being told it is. These
  are the dangerous ones, because they are invisible until they are wrong. List every one you are
  currently running on.

## Do not author the context file

**Never write the context file, and never offer to.** Not `CLAUDE.md`, not `AGENTS.md`, not a
project brief, not any file in the repository.

This command teaches noticing the gap. Showing what is missing already implies what to write, and
the person writing it themselves is what makes the result true. Report and stop.

## Never

- **Never present an inference as a known fact.**
- **Never assume an industry, a company shape or a role.** Everything known comes from what was
  actually supplied.
- **Never write a file.**
