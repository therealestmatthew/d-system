# Staging area — ungoverned by design

Park ideas here that are not yet work. Governed by [ADR-010](../04-decisions/ADR-010-idea-staging.md);
the governance audit deliberately skips this directory, so nothing here needs a code, front matter or
a catalog entry.

## What belongs here

- Plan ideas that may become plans, and may not
- Notes about work that will matter later but has no owner today
- Questions to raise when a related phase comes up

## What does not

| Not this | Because |
|---|---|
| A plan | This commits to nothing and schedules nothing |
| A backlog phase | Nothing here is queued or worked |
| `_working/` | That holds task detail for a phase that already exists; this holds ideas with no phase |
| `brain/` | That holds knowledge that is *true* and is retrieved as agent context; this holds speculation |

## The rules

**0. Ideas are recorded as given.** Never declined, merged or reworded for overlapping something that
already exists. Note the overlap inside the entry and move on — triage is a downstream pass
(idea `000007`), not a gate at capture.

**1. The idea list is an append-only event log, and `ideas.md` is generated from it.** The source is
`_data/ideas.jsonl`, one event per line. Write to it only through the writer:

```bash
uv run python tools/append_idea.py add --file idea.md   # title = first line, body = the rest
uv run python tools/append_idea.py status 000007 reviewing
```

`--title "..." --body "..."` also exist, but only for a short, plain-text title typed by hand —
prose containing a backtick, `$(...)`, a quote or a newline is not safe as a quoted shell argument.

Never edit [ideas.md](ideas.md) by hand — it is regenerated by `tools/generate_ideas_md.py` and the
test fails on any difference. "Append-only" is no longer a rule anyone has to keep: a status change
appends an event and rewrites nothing, so immutability is a fact about the bytes.

Statuses are `open`, `triaged`, `reviewing`, `promoted` and `discarded`, and they move forward only.
(`investigating` was the old markdown vocabulary; `reviewing` replaced it in
[PLAN-016](../01-plans/PLAN-016-idea-record-system.md).) A discarded idea may be revisited **once**;
after that a second discard is permanent, because something worth a third look is a new idea that
deserves its own entry rather than a footnote in this one's history.

A discarded idea stays visible with its history. The record of what was considered and rejected is
worth as much as the record of what was kept, and an idea that can be quietly removed is one that
will be raised again by someone who never learns it was already settled.

**2. Every entry ends in a status, not in deletion.** "Graduating" means becoming a plan, a
requirement or a phase; the writer requires `--promoted-to` naming which, so a terminal state
cannot fail to say what it produced. Pruning during the systems review means **marking `discarded`**,
not removing anything.

**3. Notes that are not ideas may be deleted.** Rule 1 governs `ideas.md`. Loose working notes
elsewhere in this directory are ordinary scratch and carry no such promise.

**4. [ideas-priority.yaml](ideas-priority.yaml) orders which open ideas to look at next — it is
hand-edited, not part of the append-only log.** It holds a plain `next_up` list of idea IDs, the
same shape as `backlog.yaml`'s own `next_up`
([PLAN-019](../01-plans/PLAN-019-idea-priority-queue.md)). Anyone reordering the queue edits this
file directly; git history is the audit trail, the way it already is for `backlog.yaml`'s
`next_up`. Only ideas that are `open` or `triaged` may appear in it —
`uv run python -m src.governance` rejects an entry naming an unknown idea or one that has moved
past triage (`reviewing`, `promoted`, `discarded`).

## Files

- [ideas.md](ideas.md) — the running list, generated from `_data/ideas.jsonl`
- [ideas-priority.yaml](ideas-priority.yaml) — the priority queue described in rule 4
- `codex-answers.md` — pre-existing notes
