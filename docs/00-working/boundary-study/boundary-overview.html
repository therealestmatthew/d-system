6. Options A, B and C

What each option commits to, the study's recommendation and the validation's re-assessment. This page does not choose.

Option A: One repository, explicit contracts

Keeps together
All four concerns and the framework
Separates
Nothing now; ownership and crossings are written down and checked
Cost
Lowest. Needs discipline so the boundaries hold; registry statuses must be corrected first
Extraction trigger
A concern shows an independent audience, release need and stable contract
Study (ARCH-012): Recommended now.
Validation re-assessment: Still the lowest-cost fit: the realization core has one registered system, and it is planned; the idea log is read by the workbench API and the pipeline, and one backlog lock table covers all work. Two supporting statements need correcting (claim load, plugin).

Option B: Prepare selective extraction

Keeps together
Source records (portfolio, idea log) and everything not extracted
Separates
One proven capability: the plugin, the workbench or the framework
Cost
Versioning, compatibility, publishing, cross-repository governance
Extraction trigger
A candidate meets all five preconditions: contract, independent tests, audience, maintainer, change pressure
Study (ARCH-012): Conditional future path; do not nominate a candidate yet.
Validation re-assessment: Stronger than the study shows: the idea-realization plugin is already packaged for other repositories with 497 tests, but CI does not run them, 3 fail, and no audience or release cadence is recorded.

Option C: Split now into four repositories

Keeps together
Nothing across concerns
Separates
Personal, realization, workbench and framework, each versioned
Cost
High: migration, duplicated governance, external contracts for planned systems, loss of atomic changes
Extraction trigger
Every concern has stable ownership, interfaces, release need and migration resources
Study (ARCH-012): Rejected.
Validation re-assessment: The corrected evidence strengthens the rejection: the realization core has no implemented system to move, and the workbench reads the idea log directly.
