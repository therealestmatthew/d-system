# Templates

Reusable templates for HTML generation and styling.

| Directory | Purpose |
|---|---|
| `html/` | HTML page and component templates — base layouts, section blocks, composable page structures |
| `styles/` | CSS/style definitions, design tokens, theme files tied to specific HTML template families |

## The library: declarations and population methods

`html/library.yaml` declares every template under `html/`: its family, and how it is populated
(`REQ-021` R05 and R06):

- `slot-fill`: every `{{SLOT}}` is filled deterministically from data;
- `ai-adaptation`: an agent adapts the template;
- `both`: the slots listed in `ai_slots` are the agent's, and the rest are filled
  deterministically first.

Canonical-markup catalogues such as `house-components.html` are declared with `reference: true`
and are never rendered.

`tools/template_library.py` reads the declarations and dispatches on them. A `slot-fill` template
comes back as a page or fragment. An `ai-adaptation` or `both` template comes back as an
adaptation brief: the partly filled template, the agent's slots and the data. Nothing calls a
model.

    uv run python tools/template_library.py list                  # every template, as JSON
    uv run python tools/template_library.py show atlas-page.html  # one declaration and its slots
    uv run python tools/template_library.py render house-page.html --data DATA.json --out PAGE.html

**Adding a template.**

- *A file in an existing family:* name it to match the family's pattern (`overview-*.html`,
  `lit-report-*.html`). It is declared already.
- *A file that needs its own method, or a new family:* add an entry to `html/library.yaml`.

Neither change touches a generator. `template_library.py` refuses an undeclared file, an entry
that matches no file, and an `ai_slots` name the template does not have. Each template documents
its slots in a leading `<!-- ... -->` comment, which is removed before filling.

The existing generators keep their own template loading, so their output does not depend on the
library. The library's tests replay every fill `tools/generate_overview.py` and
`tools/generate_engine_pages.py` make, and the `--specimen` fill of `tools/generate_house_css.py`,
through it and compare the bytes. A family's `inline_styles` is its base stylesheets only; a page
with styles of its own, such as the engine's backlog graph page, supplies `{{INLINE_STYLES}}`
itself.

## HTML Generation System

Templates here are consumed by the HTML Generation Framework:
- Raw source data (from `_data/` or DuckDB) feeds into templates
- Deterministic generation scripts live in `tools/` or `src/`
- React/FastAPI interface in `ts/` + `src/` drives generation, previews results, and triggers agentic workflows
- Output pages can be grouped into dynamically composable multi-page frameworks
